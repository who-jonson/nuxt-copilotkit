# AGENTS.md

Guidance for coding agents working on `nuxt-copilotkit`, a Nuxt module that integrates [CopilotKit](https://copilotkit.ai) (`@copilotkit/vue` + `@copilotkit/runtime`) into Nuxt apps.

Read [`ARCHITECTURE.md`](./ARCHITECTURE.md) before changing module code. It is the source of truth for layering, config flow, the SSR boundary and `ModuleOptions`.

## Layout

| Path | Purpose |
|---|---|
| `src/module.ts`, `src/options.ts` | Module entry and `ModuleOptions` |
| `src/devtools.ts` | Nuxt DevTools integration (dev only) |
| `src/runtime/` | Code shipped to the consumer's app and server |
| `client/` | DevTools iframe app |
| `playground/` | Manual and E2E playground |
| `test/` | Vitest suites and Nuxt fixtures |
| `docs/` | Design and planning documents |

## Commands

Package manager is pnpm (see `packageManager` in `package.json`).

```bash
pnpm install
pnpm dev:prepare   # stub build + nuxi prepare for client and playground
pnpm dev           # playground
pnpm lint          # eslint
pnpm lint:fix
pnpm test          # vitest run
pnpm prepack       # build the module and the DevTools client
```

Run `pnpm lint:fix` then `pnpm lint` before finishing any change. Run `pnpm test` for anything touching `src/`.

## Conventions

- **TypeScript imports are extensionless** (`../utils/session`, never `../utils/session.ts`).
- **Never edit `tsconfig.json` by hand.** Nuxt generates it; configure through `nuxt.config.ts` / module hooks.
- **Typecheck with `vue-tsc`** (`pnpm test:types`); mkdist also uses it to emit `.vue` declarations.
- **Dependency versions come from the pnpm catalogs** in `pnpm-workspace.yaml` (`catalog:prod` / `catalog:dev`). Do not put inline version ranges in `package.json`.
- Use Nuxt Kit helpers (`addServerHandler`, `addPlugin`, `addComponent`, `addImportsSources`, `useRuntimeConfig`, ...) rather than reimplementing them.
- Config flows one way: `ModuleOptions` -> `runtimeConfig` (private `copilotkit`, public `public.copilotkit`). Never read module options from runtime code directly.
- Keep SSR output identical to the client's first render; CopilotKit browser code must not be evaluated on the server.
- New files get a short file-level header comment; exported functions, classes and types get doc comments; comments explain *why*, not *what*.
- Match existing style; `pnpm lint:fix` is the formatter of record.

## Tests

- Vitest with `@nuxt/test-utils`; fixtures live in `test/fixtures/*`.
- Do not call real model providers from tests. Mock `@copilotkit/runtime` or use the playground mock agent.
- Test runs may rewrite `.nuxtrc`; check `git diff .nuxtrc` and restore it before committing.

## Public repository: what must never be committed

This repository is published publicly. Do not add any of the following to tracked files, commit messages, issues, PR text or documentation:

- Secrets: API keys, tokens, `.env` contents, private keys, signing material. Local keys go in a gitignored `.env`.
- Internal or private URLs, hostnames, registry mirrors, proxy or corporate-network settings, and internal ticket or system identifiers.
- Absolute local paths, usernames, or machine-specific configuration.
- Agent, tooling or process state: scratch notes, session logs, task or plan state files, handoff notes, review transcripts, worktree directories. These belong in gitignored local directories (`.pi/`, `.optimus/`, `.agents/`, `.claude/`), never in tracked paths.
- Git worktrees live at `.<harness>/worktrees/<name>` in the folder of the harness that creates them, never in a tracked path or another harness's folder. Logs and scratch files for work in a worktree go in that worktree's own `.<harness>/` folder; create it first, because a fresh worktree has none. A harness not listed above needs a `.gitignore` entry before its first use.
- Model or agent attribution lines (`Co-authored-by`, "generated by", etc.) in commits or files.
- Unreviewed vendored or copied third-party code and any content whose license is unclear.

Before staging, scan the diff for the items above (`git diff --cached`). When in doubt, leave it out and ask.

## Commits

Small, focused commits with conventional-style messages (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`). Do not commit unless asked. Never force-push.
